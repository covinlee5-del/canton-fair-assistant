# 08 - 阶段 2 验收操作手册（照着做就行）

> 这本手册只讲三件事：**你动手做哪几步**、**看到什么才算对**、**出问题怎么办**。
> 全程不需要写代码：在 PowerShell 里粘贴命令，在 Chrome 里点几下。
> 总耗时约 60–90 分钟，可分 2–3 次做完，每部分都能单独停下。
> 配套文档：`docs/verification-results.md`（要填的记录表）、`docs/04-页面读取验证方案.md`（探针协议依据）。

## A. 在本机跑命令（约 10 分钟）

### A1 打开 PowerShell

两种方式任选：

- 按 `Win + X`，在弹出菜单里选「终端」或「Windows PowerShell」；
- 或按 `Win` 键，搜索框输入 `PowerShell`，点「Windows PowerShell」。

打开后是一个深色或蓝色的窗口，可以在里面粘贴命令（右键即粘贴）。

### A2 确认 Node.js 已安装

```powershell
node -v
```

| 你看到 | 说明 | 下一步 |
|---|---|---|
| `v20.x` / `v22.x` / `v24.x` 之类 | 正常 | 继续 A3 |
| `无法将"node"项识别为 cmdlet…` | 没装 Node | 去 <https://nodejs.org> 下载 **LTS** 版本，双击安装，**所有选项保持默认**（确保勾选 Add to PATH），装完**关掉终端重开**，再验一次 |

### A3 进入项目目录

```powershell
cd D:\RDplug-in\canton-fair-assistant
```

预期：提示符前面变成这个路径。
若提示"找不到路径"，说明目录名拼错，或项目不在 D 盘；可在资源管理器打开该项目文件夹，在地址栏输入 `powershell` 后回车，会自动定位到该目录。

### A4 安装依赖

```powershell
npm install
```

预期：运行 1–3 分钟，最后出现 `added N packages` 或 `up to date`。

- 出现 `npm WARN` → **可以忽略**（只是警告）。
- 出现 `npm ERR!` → **停下来**，把整段报错复制下来发我（见 A8）。

### A5 类型检查

```powershell
npm run typecheck
```

预期：**没有任何输出**（没有输出就代表 0 错误）。
如果出现 `error TS...`，把整段复制给我。

### A6 跑测试

```powershell
npm test
```

预期结尾是这样的（关键数字是 **8** 和 **72**）：

```text
 Test Files  8 passed (8)
      Tests  72 passed (72)
```

### A7 构建

```powershell
npm run build
```

预期：出现 `✓ built in ... ms`，并在项目目录下生成 `dist\` 文件夹。

请打开 `D:\RDplug-in\canton-fair-assistant\dist` 核对，应该看到：

```text
manifest.json
background.js
content.js
sidepanel.html
options.html
icons\          （里面 3 个 png）
assets\         （若干 js / css）
```

### A8 把结果发给我（推荐一次性做完）

在 A3 的目录下执行下面这一行，会把三条命令的输出同时存成文件：

```powershell
npm run typecheck 2>&1 | Tee-Object -FilePath verify-output.txt; npm test 2>&1 | Tee-Object -Append -FilePath verify-output.txt; npm run build 2>&1 | Tee-Object -Append -FilePath verify-output.txt
```

然后把 `verify-output.txt` 的内容贴给我（或只贴失败的那一段）。
**注意**：命令是三条依次执行的，中途不要关窗口。

### A9 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `无法加载文件 …npm.ps1，因为在此系统上禁止运行脚本` | PowerShell 执行策略限制 | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，输入 `Y` 回车，**重开终端**再试 |
| `EPERM` / `operation not permitted` | 安全软件或权限拦截 | 右键 PowerShell「以管理员身份运行」重试；仍失败把完整输出发我 |
| `npm install` 卡住 / 超时 | 网络到 npm 官方源慢 | 改用镜像：`npm install --registry=https://registry.npmmirror.com` |
| `node -v` 版本低于 18 | Node 太旧 | 装最新 LTS，重开终端 |
| 提示 `dist` 已存在或权限不足 | 文件被占用 | 关掉 Chrome 里已加载的旧扩展，或重启终端重试 |

## B. 把扩展装进 Chrome（约 5 分钟）

> 需要 Chrome **114 或更高**（侧边栏 Side Panel 功能要求）。地址栏输入 `chrome://version` 可看版本。

### B1 打开扩展管理页

地址栏输入（复制粘贴即可）：

```text
chrome://extensions
```

### B2 打开「开发者模式」

页面**右上角**有一个「开发者模式」开关 → 打开。
打开后会多出三个按钮：加载已解压的扩展程序 / 打包扩展程序 / 更新。

### B3 加载扩展

1. 点左上角 **加载已解压的扩展程序**；
2. 在弹出的文件选择框里，定位到 `D:\RDplug-in\canton-fair-assistant\dist`；
3. **选中 `dist` 文件夹本身**（点一下文件夹即可，不要进去选里面的文件），点「选择文件夹」。

预期：列表出现一张卡片「广交会推广助手」，版本 `0.1.0`，并且**卡片上没有红色文字**。
若有红色「错误」按钮，点开把内容复制给我。

> 如果加载/重载时 Chrome 弹出权限提示（「读取和更改您在小红书网站上的数据」），点**允许**。这是预期行为，不是出问题了。
> 如果列表里**同时存在**一张指向 `阶段2-站点权限测试版` 的旧卡片，请先点「移除」删掉它，只保留指向 `dist` 的那张，否则你会验错对象。

### B4 固定到工具栏

点浏览器右上角的拼图图标 🧩 → 找到「广交会推广助手」→ 点它右边的图钉 📌。
之后工具栏就有一个常驻图标，方便打开侧边栏。

### B5 打开管理页（Options）

任选一种：

- 卡片上点「详情」→ 页面往下滚，找到「扩展程序选项」→ 点开；
- 或卡片右下角「•••」→「选项」。

会打开一个新标签页，左侧有 6 个导航：首页 / 任务 / 笔记 / 文案 / 统计 / 设置。

### B6 记下扩展 ID

扩展卡片下方有一行 `ID: 一长串字母`，复制记下来（排查问题、看控制台时要用）。

## D. 真实页面探针（约 20–30 分钟）

### D0 三条纪律（请务必遵守）

1. 探针**只读**：不点赞、不评论、不关注、不私信、不改任何设置；
2. 不要用任何自动化脚本去刷页面；
3. 只在**你手动点按钮**的时刻读取，不后台轮询。

### D1 前置条件

- Chrome ≥ 114，已装好扩展（B 部分）；
- 已在**同一个浏览器**里登录你自己的小红书账号；
- 准备好一个记事本文件（或用 `docs/verification-results.md` §6 的记录模板）。

### D2 11 步协议

每步操作完，**在当前标签页**打开侧边栏 → 点「读取当前页面诊断」→ 点「复制诊断 JSON」→ 粘贴到记事本。

| 步骤 | 操作 | 预期 | 记录（填关键信号值） |
|---|---|---|---|
| 1 | 打开 `https://www.xiaohongshu.com`，确认已登录 | 首页正常显示 | pageType= |
| 2 | 搜索「广交会」，等结果加载完 | 出现笔记卡片 | — |
| 3 | 在**这个标签页**点扩展图标打开侧边栏 | 侧边栏打开且不消失 | — |
| 4 | 点「读取当前页面诊断」 | `pageType=search_results`，`noteSections > 0`，无错误码 | pageType / noteSections / exploreLinks / totalCandidates |
| 5 | 向下滚动加载更多，再读取一次 | 候选数比第 4 步增加 | totalCandidates（前→后） |
| 6 | 换关键词「interpreter」搜一次，再读取 | 候选集合变化 | totalCandidates |
| 7 | 打开任意一篇笔记的详情页，再读取 | `pageType=note_detail`（或明确提示不支持） | pageType |
| 8 | **新开标签页**直接打开小红书（不在该页点图标）后读取 | 站点权限下**应能正常读到**（不再报权限不足；原因见 §0 的站点权限说明与 `docs/04` 修订） | errorCode（应为空）/ totalCandidates |
| 9 | 退出登录后再读取 | 阶段 2 只记录原始信号：`loginWallDetected` 目前硬编码 `false`，**不要求出现「需要登录」提示**；真实判定排入阶段 3 | errorCode / signals |
| 10 | 触发验证码/风控场景后读取（没触发可跳过，注明） | 有明确提示且**不尝试绕过** | errorCode |
| 11 | 汇总：日期、Chrome 版本、`selectorVersion`、各步 JSON 快照 | 形成完整记录 | — |

> **第 8、9 步的预期在阶段 2 验收后改过一次**（原写法是按 `activeTab` 与"登录墙已实现"设计的，两者都不成立）。现在的判定标准以本表为准。

```text
selectorVersion：

{
}

```
