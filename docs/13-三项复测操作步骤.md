## 0. 执行前必须做的一件事

### 0.1 重新加载扩展

1. 地址栏输入 `chrome://extensions` 回车
2. 找到「广交会推广助手」
3. 点该卡片上的 **⟳ 重新加载**

**为什么必须做**：代码已在 2026-10-19 12:04 重新构建进 `dist/`，但 Chrome 只在点「重新加载」时才去读新文件。不点，测的是旧代码，三项都会失败。

### 0.2 三个界面在哪里

| 界面 | 怎么打开 | 用来干什么 |
|---|---|---|
| **侧边栏** | 点浏览器工具栏上的扩展图标 | 读取当前页面、看诊断数字 |
| **管理页** | 侧边栏或扩展菜单里的「打开管理页」 | 看笔记列表、改状态、批量操作、看活动 |
| **管理页导航** | 管理页顶部：首页 / 任务 / 笔记 / 文案 / 活动 / 统计 / 设置 | 切换页面 |

### 0.3 侧边栏上要看的字段（后面会反复提到）

读取后侧边栏「最近读取结果」区域会显示：

```
页面类型    搜索结果页 / 笔记详情页 / 其他页面
页面地址    www.xiaohongshu.com/search_result_ai
识别卡片    N 个
成功提取    N 条（其中 N 条信息不完整）
跳过卡片    N 个
读取时间    2026-10-19 HH:mm
提取器版本  xhs-1.0.0
本次入库    新增 N / 已存在 N / 失败 N
```

下面还有错误列表（有错才显示）、「复制诊断 JSON」按钮、「原始诊断 JSON」折叠条。

### 0.4 一条核心自检规则（本次修复新增）

> **成功提取 + 跳过卡片 = 识别卡片**

这三张卡片在搜索结果页**必须**对得上。对不上就是 bug，记下来。

## 复测 A：滚动加载后去重（`docs/verification-results.md` §8 第 6 行）

### A.1 目的

证明两件事：
1. 滚动加载出更多卡片后，「识别 / 提取 / 跳过」三个数字自洽（上次这组数字是 30/0/0，数学上不可能）。
2. 再读一次，已经入库的笔记不会被重复记录。

### A.2 前置

- 已登录小红书
- 已按 §0.1 重新加载扩展

### A.3 步骤

| # | 操作 | 检查点 |
|---|---|---|
| 1 | 打开小红书，搜索 `广交会`，等卡片显示出来 | 能看到笔记卡片网格 |
| 2 | **只用鼠标滚轮往下滚 3–4 屏**，然后滚回顶部 | ⚠️ **绝对不要点击任何卡片** |
| 3 | 点工具栏扩展图标，打开侧边栏 | 侧边栏出现 |
| 4 | 侧边栏「当前任务」下拉，选中你自己的任务（例：`广交会翻译机会`） | 按钮变亮 |
| 5 | 点 **「读取当前页面笔记」** | 按钮文字短暂变成「读取中…」 |
| 6 | 看侧边栏「页面类型」 | **必须是「搜索结果页」** |
| 7 | 记录三个数字：识别卡片 / 成功提取 / 跳过卡片 | 必须满足 `提取 + 跳过 = 识别` |
| 8 | **再点一次「读取当前页面笔记」** | 第二次读取 |
| 9 | 记录「本次入库」那一行的三个数字 | 新增 / 已存在 / 失败 |
| 10 | 打开管理页 → 导航点「笔记」→ 任务下拉选同一个任务 | 表格出现笔记行 |
| 11 | 看「笔记列表」标题右边的 `N 条` | 这就是当前筛选下的笔记总条数 |

### A.4 预期结果

**第 6 步**：`页面类型` = `搜索结果页`

**第 7 步**（数字示例，具体值会不同）：

```
识别卡片   30 个
成功提取   28 条
跳过卡片    2 个        ← 28 + 2 = 30 ✅
```

**第 9 步**：

```
本次入库   新增 0 / 已存在 28 / 失败 0
```

「已存在」接近第 7 步的「成功提取」数 = 去重生效。

**第 11 步**：「笔记列表」右边的 `N 条` = 第一次读取时的总数 + 第 9 步的新增数。
（同一个数字也可以从侧边栏当前任务区块的「笔记总数」看到，两处应当一致。）

### A.5 判定

| 现象 | 判定 |
|---|---|
| 第 6 步是「搜索结果页」，且第 7 步 `提取 + 跳过 = 识别` | ✅ 缺陷 E 已修好 |
| 第 9 步「已存在」接近「成功提取」数 | ✅ 去重生效 |
| 第 11 步总条数对得上账 | ✅ 通过 |
| 又出现「识别卡片 30 / 提取 0 / 跳过 0」 | ❌ 缺陷 E 未修好 |
| 第 6 步显示「笔记详情页」 | ⚠️ 操作问题，不是 bug — 见 A.6 |

### A.6 如果页面类型显示「笔记详情页」

说明你在滚动时点开了某条笔记。小红书的详情页是**叠加层**，URL 会变成 `/explore/{id}`，但底下搜索结果的卡片还在页面里没卸载——这正是上次「识别卡片 30 / 提取 0 / 跳过 0」的成因。

**处理**：点浏览器的**后退**按钮（或按 `Alt + ←`）回到搜索结果页，确认「页面地址」变成 `search_result` 开头，然后从 A.3 第 5 步重做。

### A.7 要记录并回填的内容

```
第 7 步：识别卡片 ___ / 成功提取 ___ / 跳过卡片 ___
第 9 步：新增 ___ / 已存在 ___ / 失败 ___
第 11 步：管理页笔记总条数 ___
```

**回填位置**：`docs/verification-results.md` → 第 6 节（§8）表格 → **第 6 行**，把现在那段「未通过（暴露 bug，已修复待复测）」替换为真实数字与结论。

## 复测 C：批量非法转移必须拒绝并说明原因（`docs/11-阶段4任务清单与操作手册.md` §6 第 9b 项）

### C.1 目的

证明两件事：
1. 批量操作是「全有或全无」——只要批里有一条状态不允许，整批都不执行，任何一条的状态都不会被改。
2. 被拒绝时会说清楚**是哪一条、为什么**（旧版本只说「输入内容不合法，请检查后重试。。」）。

### C.2 为什么需要"混合"选择

状态机是单向的（`docs/03-数据模型.md`）：`新发现 → 已审核 → 待联系 → 已完成推广 → 已收到回复 → 已建立联系`，不能倒退。

`新发现 → 已审核` 是**合法**转移。所以如果你勾的两条都还是「新发现」，批量标为已审核会**成功**，本来就不该报错——上次就是这个原因，"没看到报错"不是 bug。

要触发拒绝，必须勾**一条已经推进到「已完成推广」的** + **一条还是「新发现」的**。

### C.3 步骤

**第一部分：把一条笔记推进到「已完成推广」**

| # | 操作 | 检查点 |
|---|---|---|
| 1 | 打开管理页 → 导航点「笔记」→ 任务下拉选你自己的任务 | 表格出现笔记行 |
| 2 | 找一条「状态」列显示为 **新发现** 的笔记，记住它的**标题** | 后面要核对 |
| 3 | 在该行点 **「标为已审核」** | 状态列变成「已审核」，按钮变成「标为待联系」 |
| 4 | 在该行点 **「标为待联系」** | 状态列变成「待联系」，按钮变成「标记已推广」 |
| 5 | 在该行点 **「标记已推广」** | 状态列变成「已完成推广」，按钮变成「标记已回复」 |

> 注意：这三个按钮是**依次出现**的，每点一次上一个按钮就消失。看不到「标为待联系」说明第 3 步没生效。

**第二部分：核对活动记录**

| # | 操作 | 检查点 |
|---|---|---|
| 6 | 导航点「活动」 | 活动表格 |
| 7 | 确认刚才那条笔记新增了 **3 条**记录 | 时间、任务、动作三列都有值 |
| 8 | 特别检查「任务」列 | 应显示**任务名称**，不是一串 UUID |

> 第 8 步同时复验缺陷 B（活动页曾显示原始 UUID）。

**第三部分：构造非法批量**

| # | 操作 | 检查点 |
|---|---|---|
| 9 | 导航点回「笔记」 | 回到笔记表格 |
| 10 | 勾选刚才那条（现在是「已完成推广」）的复选框 | 上方出现「已选 1 条」和两个批量按钮 |
| 11 | 再勾选**另一条仍是「新发现」**的笔记 | 显示「已选 2 条」 |
| 12 | 点 **「批量标为已审核」** | — |
| 13 | 看批量按钮**正下方**出现的红字 | 逐字记录 |
| 14 | 检查这两条笔记的状态 | 两条都不能变 |

### C.4 预期结果

**第 13 步**红字（标题部分是那条已推广笔记的真实标题）：

```
整批未执行：有 1 条笔记当前状态不允许变更为「已审核」（「<那条笔记的标题>」当前为已完成推广）。请先取消勾选这些笔记。
```

**第 14 步**：
- 那条「已完成推广」的还是「已完成推广」
- 那条「新发现」的还是「新发现」

### C.5 判定

| 现象 | 判定 |
|---|---|
| 红字点名到具体标题和「当前为已完成推广」 | ✅ 缺陷 D 已修好 |
| 红字出现，且两条状态都没变 | ✅ 「全有或全无」成立 |
| 只有「输入内容不合法，请检查后重试。」且末尾有「。。」 | ❌ 缺陷 D 未修好（旧文案） |
| 完全没有红字 | ❌ 检查第 3–5 步是否真的把一条推到了「已完成推广」 |
| 「新发现」那条被改成了「已审核」 | ❌ 严重：事务语义被破坏，部分更新了 |
| 红字出现在页面**最顶部**而不是批量按钮下方 | ⚠️ 缺陷 C 回归，记录位置 |

### C.6 要记录并回填的内容

## 5. 三种最容易犯的错（每一条都真实发生过）

### 5.1 忘了点「⟳ 重新加载」

**症状**：三项全部失败，且表现和修复前一模一样。

**原因**：Chrome 不会因为 `dist/` 变了就自动更新已加载的扩展。

**处理**：`chrome://extensions` → ⟳ 重新加载 → 关掉侧边栏再重开 → 重做。

### 5.2 复测 A 时点进了笔记

**症状**：「识别卡片 30 / 提取 0 / 跳过 0」，页面类型显示「笔记详情页」。

**原因**：滚动或回顶部时不小心点到了卡片，URL 变成了 `/explore/{id}`。

**处理**：按 `Alt + ←` 退回搜索结果页，确认页面地址是 `search_result` 开头，重做。

### 5.3 复测 C 勾了两条都是「新发现」

**症状**：点批量后没有红字，两条都变成了「已审核」。

**原因**：`新发现 → 已审核` 是合法转移，不构成非法批量。

**处理**：先把一条按 C.3 第 3–5 步推到「已完成推广」，再勾它 + 另一条「新发现」的。

## 6. 给自动化执行者（若由 Codex 驱动浏览器）的元素定位

| 元素 | 定位方式 |
|---|---|
| 侧边栏读取按钮 | 可见文字 `读取当前页面笔记`（读取中变成 `读取中…`） |
| 管理页入口 | 可见文字 `打开管理页` |
| 管理页导航 | 可见文字：`首页` `任务` `笔记` `文案` `活动` `统计` `设置` |
| 行内状态按钮 | 可见文字：`标为已审核` `标为待联系` `标记已推广` `标记已回复` `标记已联系` |
| 单行复选框 | `aria-label` = `选择<笔记标题>` |
| 全选复选框 | `aria-label` = `全选当前列表` |
| 批量按钮 | 可见文字 `批量标为已审核` / `批量标为不相关` |
| 批量错误提示 | `role="alert"` 的 `<p>`，位于批量按钮下方 |
| 侧边栏错误横幅 | `role="alert"` 的 `.error-banner` |

**状态列的值**只能是这七个之一：`新发现` `已审核` `待联系` `已完成推广` `已收到回复` `已建立联系` `不相关`。

**注意**：不要用"稍后再说"的方式跳过 §0.1 重新加载；不要在没有真实数据的情况下把任何一项标成通过。
