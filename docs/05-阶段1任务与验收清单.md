## 5. 可直接实现 vs 必须真实页面验证

### 5.1 无需真实页面即可实现并测试 ✅

| 能力 | 说明 |
|---|---|
| 数据模型与本地存储（chrome.storage + IndexedDB） | Repository + 迁移，fake-indexeddb 集成测试 |
| 任务/文案 CRUD、默认任务/默认文案 | 业务服务 + 单测 |
| 笔记规范化、链接规范化、去重 | 纯函数，表驱动单测 |
| 相关性评分（关键词/场景/时间/负向词） | 纯函数，单测 |
| 状态机与推广状态管理 | 纯函数，单测 |
| 统计计算 | 纯函数，单测 |
| JSON 导入校验与导出 | 单测 + 回环集成测试 |
| 全部 UI 页面（侧边栏 + 管理页） | 组件测试 |
| 模拟页面提取测试（fixtures） | jsdom 测试 |

### 5.2 必须真实页面验证后才能声明可用 ⚠️

| 能力 | 验证方式 | 当前状态 |
|---|---|---|
| 小红书搜索结果页的笔记选择器有效性 | docs/04 §3 协议步骤 1–7 | **待验证** |
| 搜索卡片是否展示发布时间 | 同上步骤 4 | **待验证** |
| activeTab 授权在侧边栏流程中的保持性 | 同上步骤 8 | **待验证** |
| 登录墙/验证码信号识别 | 同上步骤 9–10 | **待验证** |
| 滚动加载后重读与去重 | 同上步骤 5–6 | **待验证** |
| DOM 结构长期稳定性 | docs/04 §6 回归机制 | **持续观察** |

以上任何一项未实测通过，交付说明中都必须保持"待验证"标记，不得声称完成。
