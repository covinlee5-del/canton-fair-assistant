# 01 · 需求复核与风险分析

## 1. 总体结论

需求整体**可实现**，没有技术上完全不可行的条目。核心读取方式——读取用户正常打开页面的可见 DOM——是浏览器扩展的标准能力，不属于"爬虫接口"范畴；PRD 已把一切对外互动限定为用户手动完成，与平台规则一致。

结论成立的两个硬前提（也是本项目不可违反的约束）：

1. Content Script 只读取 DOM 中可见的笔记信息，不读取 Cookie、密码、会话凭证，不拦截网络请求。
2. 插件不执行任何自动对外互动（发布、点赞、关注、私信）。

主要不确定性集中在 **小红书页面结构稳定性** 和 **activeTab 权限在侧边栏流程中的保持性**，两者都必须通过真实页面实测确认，模拟测试不能替代。

## 2. 需要澄清或修正的点

### 2.1 Popup 生命周期与"边浏览边读取"流程冲突 ⚠️ 影响架构

MV3 弹出窗口（popup）在失焦时立即销毁。"用户在 popup 点击读取 → 回到页面继续浏览 → 再看结果"的流程中，popup 每次打开都是全新实例，异步读取的回调可能随 popup 关闭而丢失。

**处理方案**：采用 **Side Panel（侧边栏，Chrome 114+）** 作为主界面——侧边栏在用户浏览页面时保持打开，天然支持"浏览 → 读取 → 看结果 → 再浏览"闭环；长列表管理功能（任务/笔记/文案/统计/设置）放在独立的 Options 管理页。详见文档 02。**需用户确认。**

### 2.2 "页面中可见的发布时间"可能根本不存在 ⚠️ 必须实测

小红书搜索结果卡片的字段随版本与实验分组变化：时间字段可能显示相对时间（如"3 天前"），也可能完全不显示。数据模型已允许 `publishedAt: null`，需进一步明确：

- 时间为 `null` 时，时间相关性规则计 0 分（中性，不惩罚）；
- UI 显示"时间未知"，不伪造时间。

真实页面能否读到时间，是文档 04 验证方案的第 5 项验证点。

### 2.3 activeTab 授权在侧边栏交互下能否保持 ⚠️ 必须实测

`activeTab` 在用户点击扩展图标时授予当前标签页，直到该标签页导航到其他源或关闭。小红书的站内搜索是 SPA 同源导航，理论上授权保持；但存在失败场景（用户换标签页打开新页面、授权超时、浏览器策略差异）。

**处理方案**：先以 activeTab + scripting 起步实测；若实测不稳定，再评估**仅限 `*.xiaohongshu.com` 的站点级 host_permissions**（需要用户批准，绝不申请 `<all_urls>`）。**需用户确认策略。**

### 2.4 登录墙 / 验证码场景未定义错误态

未登录或触发风控时，搜索结果页可能没有笔记卡片，或要求完成验证。若不加区分，插件会误报"没有笔记"。

**处理方案**：新增错误码 `LOGIN_REQUIRED`、`CAPTCHA_OR_RISK_CONTROL`，提示用户自行登录/完成验证后重试。**绝不尝试绕过**，这是 PRD 第十节的硬性要求。

### 2.5 删除任务时笔记的归属未定义

PRD 6.7 要求处理但未给策略。

**处理方案**：删除任务不删除笔记（笔记可能关联多个任务），仅解除 `taskIds` 关联；失去全部关联的笔记标记为"未关联任务"（孤儿），在设置页提供批量清理。活动记录永久保留（审计用途）。

### 2.6 "读取当前页面"必须先有当前任务

流程 C 说"将新笔记加入任务结果列表"，但未说明未选任务时怎么办。

**处理方案**：设置中保存 `defaultTaskId`；读取前必须存在活动任务，否则引导用户先创建/选择任务。任务与相关性评分绑定（同一笔记在不同任务下评分不同，见文档 03 的 `relevanceByTask`）。

### 2.7 扩展页面 CSP 限制开发方式

MV3 扩展页面禁止远程代码和 `eval`，Vite HMR 不能直接在扩展页面里生效。

**处理方案**：开发方式为"构建 → 加载已解压扩展 → 修改后重建 + 刷新扩展"。这不是风险，但影响开发体验预期。

### 2.8 存储配额澄清

`chrome.storage.local` 配额 10 MB，仅存设置（几 KB，绰绰有余）；任务/笔记/活动存入 IndexedDB（配额为磁盘百分比，第一版量级无压力）。**无需申请 `unlimitedStorage` 权限**。

### 2.9 "关键词语言"字段的语义

该字段不改变页面语言，只影响匹配策略：中文关键词用子串匹配；英文关键词大小写不敏感 + 词边界匹配（避免 "fair" 命中 "affair" 之类）。多语言关键词共存时逐条独立处理。该字段同时用于默认关键词推荐与展示。

## 3. 技术上不可实现的部分

**无。** 但以下能力第一版明确不实现、不验证、不声称：

| 能力 | 状态 |
|---|---|
| 调用小红书内部/未验证 API | 不实现 |
| 自动发布评论、点赞、关注、私信 | 不实现 |
| 后台持续抓取、无限滚动自动翻页 | 不实现 |
| 绕过验证码、登录墙、风控 | 不实现 |
| 云端同步 / 多账号 | 不实现（仅预留接口） |

## 4. 五大技术风险（按优先级排序）

### R1 · 小红书 DOM 结构不稳定 / 频繁变更 —— **最高风险**

| 项 | 内容 |
|---|---|
| 说明 | 小红书是重度反自动化 SPA，CSS 类名哈希化且随版本更新；卡片结构可能因实验分组不同；搜索结果卡片字段（标题/摘要/时间）不保证齐全。 |
| 影响 | 提取失败或质量下降，直接影响核心价值。 |
| 验证方法 | ① 文档 04 的验证探针在真实页面采集 DOM 信号；② 模拟页面覆盖多种结构（缺标题/缺链接/缺时间/结构变化）；③ 每次读取记录 `selectorVersion`，结构变化时可定位。 |
| 缓解措施 | 适配器隔离（`XiaohongshuPageAdapter`）；选择器集中注册并版本化；优先使用语义化锚点（笔记链接路径 `/explore/{id}` 的链接元素）而非 CSS 类名；提取失败返回明确错误而非伪造数据。 |

### R2 · 权限保持性：activeTab + 侧边栏交互能否稳定读取 —— **核心流程风险**

| 项 | 内容 |
|---|---|
| 说明 | activeTab 授权有生命周期；新标签页、跨源导航、浏览器重启都会失效。侧边栏按钮点击是否能稳定触发对当前标签页的注入，需要实测（Chrome 对"用户调用"的判定）。 |
| 影响 | 核心读取流程中断，用户挫败。 |
| 验证方法 | 阶段 2 的验证探针按文档 04 的 9 个场景逐一实测并记录。 |
| 缓解措施 | 错误提示 + 重试引导（"请在目标页面上重新点击扩展图标"）；必要时评估仅限 `*.xiaohongshu.com` 的站点权限（透明申请、用户批准）。 |

### R3 · 登录墙 / 验证码导致"无可见笔记" —— **环境风险**

| 项 | 内容 |
|---|---|
| 说明 | 未登录或触发风控时，搜索结果页没有笔记卡片或要求验证；若插件误判为"无结果"，用户会误以为功能坏了。 |
| 影响 | 读取失败且原因不明。 |
| 验证方法 | 登录态与未登录态对比测试；探针输出 `loginWallDetected / captchaDetected` 信号。 |
| 缓解措施 | 独立错误码与引导文案；绝不绕过（PRD 硬性要求）。 |

### R4 · 去重失效导致数据重复 —— **数据质量风险**

| 项 | 内容 |
|---|---|
| 说明 | 链接规范化规则错误（路径变体、查询参数、SPA 链接拼接）或指纹规则过松会导致同一笔记被重复创建，统计失真。 |
| 影响 | 重复劳动、统计不可信、复盘结论错误。 |
| 验证方法 | 链接规范化单元测试（表驱动）；模拟重复页面测试；导出→导入回环测试；真实页面"滚动后再读取"去重计数验证。 |
| 缓解措施 | 以笔记 ID（`/explore/{24位hex}`）规范化 URL 为主键；无稳定链接时用"规范化标题+作者"指纹兜底；**标题相似不等于同一条笔记**（指纹要求规范化后完全一致）；导入时按 id 合并并报告冲突。 |

### R5 · MV3 Service Worker 生命周期与多上下文数据一致性 —— **稳定性风险**

| 项 | 内容 |
|---|---|
| 说明 | MV3 Service Worker 随时可能被终止；侧边栏、管理页、SW 三处并发读写同一份 IndexedDB。若状态依赖内存，SW 被杀后数据丢失或不一致。 |
| 影响 | 数据丢失、状态错乱。 |
| 验证方法 | 手动终止 SW（chrome://serviceworker-internals）后验证数据完整；扩展重载后状态仍在；并发写测试（集成测试）。 |
| 缓解措施 | 所有写操作经 Repository 事务封装；重要状态全部持久化；任务恢复以本地记录为准，不假设内存状态；所有异步操作带错误处理并返回 `Result`。 |

## 5. 次要风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 浏览器版本 | Side Panel 需要 Chrome 114+ | README 写明版本要求；降级路径为 Popup |
| 构建工具链 | @crxjs/vite-plugin 的维护状态 | 接口隔离，可切换为手工多入口 Vite 配置（文档 02 有预案） |
| 相对时间解析精度 | "3 天前" → 近似日期 | 保存 `publishedAtRaw` 原文 + 解析结果，UI 展示原文 |
| 数据量增长 | 长期积累大量笔记 | 第一版量级可控；IndexedDB 索引按 taskIds/status 建索引 |
