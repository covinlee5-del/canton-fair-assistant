## 3. 各任务详细操作步骤

### T2.0 环境与依赖安装

**目标**：锁定工具链与依赖版本。

**操作步骤**：
1. `node -v` 确认 ≥ 18（Vite 5 要求），`npm -v` 确认可用。
2. `npm init -y` 并改写 package.json（name: canton-fair-assistant，private: true）。
3. 安装运行依赖：react、react-dom、idb。
4. 安装开发依赖：typescript、vite、@vitejs/plugin-react、vitest、jsdom、fake-indexeddb、@types/chrome、@types/react、@types/react-dom（**不安装 @crxjs/vite-plugin**，见 docs/02 ADR-001）。
5. 写入 .gitignore（node_modules/、dist/、*.local）。
6. 说明：若 Agent 沙箱无法访问 npm registry，则把命令交付用户在本机执行，并回报安装输出。

**执行命令**：

```bash
npm install react react-dom idb
npm install -D typescript vite @vitejs/plugin-react vitest jsdom fake-indexeddb @types/chrome @types/react @types/react-dom
```

**预期结果**：`npm ls` 无错误；版本以安装当日最新稳定版为准（不锁定旧版本）。

**依赖用途**（对应 PRD 质量要求第 11 条）：react/react-dom 渲染 UI；idb 提供 IndexedDB 的 Promise 封装；vite + @vitejs/plugin-react 负责构建（手工多入口，见 docs/02 ADR-001）；vitest + jsdom + fake-indexeddb 分别用于纯逻辑单测、DOM 解析测试、IndexedDB 集成测试；@types/chrome 提供 Chrome API 类型。

### T2.1 项目脚手架与构建配置

**产出文件（实际）**：package.json（scripts）、vite.config.ts、vite.content.config.ts、tsconfig.json、vitest.config.ts、sidepanel.html、options.html、public/manifest.json、public/icons/（16/48/128 三张 PNG）、scripts/make-icons.ps1、scripts/watch.mjs。

**操作步骤**：
1. package.json scripts：`build`（主构建 + 内容脚本构建）、`build:content`（仅内容脚本）、`dev`（scripts/watch.mjs 同时 watch 两个配置，改完手动刷新扩展）、`typecheck`（tsc --noEmit）、`test`（vitest run）。
2. vite.config.ts（主构建）：不使用 CRXJS；input = sidepanel.html / options.html / src/background/index.ts，`entryFileNames` 固定把 background 输出为 background.js。vite.content.config.ts：lib + IIFE 单文件 content.js。manifest.json 手写在 public/ 下，由 Vite 复制进 dist。
3. tsconfig.json：strict: true 等严格选项，禁止 any（PRD 质量要求第 1 条）。
4. vitest.config.ts：默认 node 环境；涉及 DOM 的测试文件用 `// @vitest-environment jsdom` 声明。
5. 生成占位图标：make-icons.ps1 用 System.Drawing 生成单色占位图（正式图标后补）。
6. 构建并产出 dist/。

**执行命令**：

```bash
npm run build
npm run typecheck
```

**预期结果**：构建成功；dist/manifest.json 存在且 manifest_version=3；typecheck 无错误。

### T2.2 Manifest V3 + 侧边栏 / 管理页骨架

**产出文件（实际）**：public/manifest.json（手写）、src/background/{index,message-router,lifecycle}.ts + commands/、sidepanel.html 与 options.html（项目根目录，保证产物为 dist/sidepanel.html 与 dist/options.html）、src/ui/sidepanel/（main.tsx、App.tsx、pages/home.tsx、pages/read-result.tsx）、src/ui/options/（main.tsx、App.tsx、nav.ts、pages/ 六页）、src/ui/shared/（Button、StatusTag、ConfirmDialog、ErrorBanner、useAsyncState、styles.css）、src/ui/api.ts。

**操作步骤**：
1. manifest：permissions = [storage, activeTab, scripting, sidePanel]；side_panel.default_path = sidepanel.html；options_page = options.html；action.default_title；**不声明 host_permissions**（策略已确认）。—— **阶段 2 验收后改判**：实测 `activeTab` 在「点图标开侧边栏」流程下拿不到授权，已增加 `host_permissions: ["*://*.xiaohongshu.com/*"]`（commit `6dc68af`，见 `docs/02` §6）。
2. SW 入口：`chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true })`；空消息路由占位。
3. 侧边栏 App：页头（产品名 + 当前任务占位）+ 首页卡片（读取状态占位、读取按钮禁用态）+ "打开管理页"按钮（chrome.runtime.openOptionsPage）。
4. 管理页 App：顶部导航（首页/任务/笔记/文案/统计/设置），每页占位内容。
5. 共享组件：StatusTag、Button、ConfirmDialog（阶段 2 用最简实现）。

**验证步骤（用户配合）**：
1. chrome://extensions → 开发者模式 → 加载已解压的扩展程序 → 选择 dist/ → 无 manifest 错误。
2. 点击工具栏图标 → 侧边栏打开（需 Chrome ≥ 114）。
3. chrome://extensions → 扩展程序选项 → 管理页打开，6 个导航（首页/任务/笔记/文案/统计/设置）可切换。
4. SW 状态正常（无红色错误）。

**预期结果**：两条 UI 通路可用 —— 达成验收标准第 1、3 条（"插件安装及正常启动"、"插件首页和主要页面可以正常使用"）。

### T2.3 基础层：shared / platform / data

**产出文件**：src/shared/types/*（按 docs/03 全量类型）、src/shared/utils/{ids,time,result,text}.ts、src/shared/constants/*、src/platform/*（storage/messaging/tabs/scripting/side-panel 薄封装）、src/data/{db,migrations,repository}.ts + 5 个 Repository + index.ts、tests/unit/*、tests/integration/repositories.test.ts。

**操作步骤**：
1. 按 docs/03 落地全部类型定义与枚举（**文档是唯一数据契约，字段逐一对应**）。
2. utils 实现 + 单测：crypto.randomUUID 封装（含降级）、ISO 时间工具、Result 构造器、文本规范化（trim/折叠空白/大小写）。
3. platform 层：chrome API 全部经此层调用，**其它层禁止直接 import chrome**。
4. data 层：idb 打开 DB（stores：tasks/notes/copies/activities/meta；索引：by-status、by-updatedAt、by-taskIds(multiEntry)、by-noteId、by-taskId、by-actionAt）；migrations v1；Repository 基础 CRUD 返回 Result；Settings 仓库底层用 chrome.storage.local（键 `settings`）。
5. 集成测试：fake-indexeddb 下验证 settings/task 写入→读取→更新→删除全链路；模拟写入失败必须返回 STORAGE_ERROR（不显示成功）。

**执行命令**：

```bash
npm test
```

**预期结果**：全部测试通过；覆盖空串、null、非法时间等边界。

### T2.4 任务管理基础功能

**产出文件**：src/messaging/messages.ts、src/background/message-router.ts + commands/{task-commands,settings-commands,dashboard-commands}.ts、src/services/task-service.ts、src/ui/options/pages/tasks.tsx（列表+表单）、src/ui/options/pages/task-form.tsx、src/ui/sidepanel/pages/home.tsx（当前任务显示/切换）、tests/integration/message-layer.test.ts（消息层端到端）。

**操作步骤**：
1. messages.ts：定义 task.list / task.create / task.update / task.delete / task.duplicate / task.set-status、settings.get / settings.set-default-task、get-dashboard、read-page 的消息契约（请求/响应类型）。
2. message-router：注册消息 → 分发命令；服务层返回 `Result`，命令层用 `unwrap()` 拆包（失败抛 `AppError`），路由器把"纯值或错误"包装成**单层信封** `{ok,value}` / `{ok:false,error}`。
3. task-service：校验（名称非空、至少 1 个关键词、类目合法）；duplicate 生成新 id；状态管理（ACTIVE/PAUSED/ARCHIVED）。
4. tasks.tsx：列表（名称/关键词数/类目/更新时间）、新建/编辑表单（类目下拉、关键词标签输入、关联文案占位）、暂停/复制/删除（删除必须 ConfirmDialog 确认）。
5. home.tsx：显示当前任务 + 下拉切换；无任务时引导"新建任务"。
6. service 层单测：校验规则、duplicate 逻辑、非法输入返回错误。

**验证步骤（用户配合）**：
1. 管理页创建任务"广交会翻译机会"（关键词：广交会 / Canton Fair / interpreter；类目：英语翻译需求）。
2. 编辑、复制、暂停、删除（观察确认弹窗）各一次。
3. **关闭浏览器重新打开，或 chrome://extensions 重载扩展** → 任务数据仍在（验证持久化）。
4. 侧边栏首页能切换当前任务。

**预期结果**：任务 CRUD 全链路可用且持久化 —— 对应验收标准第 4 条。

### T2.5 验证探针（只读诊断）

**产出文件**：src/content/adapters/page-adapter.ts（接口）、selectors.ts（选择器注册表 v1，仅含通用信号规则）、diagnostics.ts、xiaohongshu-adapter.ts（探针版）、src/content/index.ts（入口）、src/background/commands/read-page.ts、src/ui/sidepanel/pages/read-result.tsx。

**操作步骤**：
1. PageAdapter 接口按 docs/04 定义（isSupportedPage / getPageType / extractVisibleNotes / normalizeNote / getExtractionDiagnostics / validateExtractionResult）。
2. 探针版实现（阶段 2 只做诊断，不做正式提取）：
   - 信号收集：`a[href]` 中 /explore/ 与 /discovery/item/ 链接计数、section 元素计数、readyState、典型 SPA 根节点是否存在；
   - **不读任何文本内容、不读 Cookie/storage、URL 只保留 origin+pathname**（隐私约束，docs/04 §1）；
   - 输出 ExtractionDiagnostics（含 selectorVersion、signals、errors）。
3. read-page 命令：chrome.tabs.query 取当前活动标签 → 校验 URL 为 xiaohongshu.com → **两段式注入**（① `executeScript({files:["content.js"]})` 让内容脚本把诊断写到 isolated world 的全局键；② `executeScript({func})` 读回该结果 —— 因为 IIFE 打包后的脚本完成值为空，不能依赖 `files` 注入的返回值）→ 落库并回传诊断；PERMISSION_DENIED / UNSUPPORTED_PAGE / PAGE_NOT_READY 路径返回对应错误码与用户文案（docs/04 §5 映射表）。
4. 侧边栏"读取诊断"按钮 + 结果卡片（诊断 JSON + 一键复制）+ 错误提示（含重试引导）。
5. 诚实降级声明：LOGIN_REQUIRED / CAPTCHA 的判定模式**不在阶段 2 编码** —— 探针先输出原始信号，等用户在真实页面执行测试协议后，依据实测信号模式在阶段 3 编码判定规则。

**执行命令**：

```bash
npm run build && npm test
```

**验证步骤（用户必须在真实小红书页面执行，docs/04 §3 协议步骤 1–8）**：
1. 登录小红书 → 搜索"广交会" → 等结果加载。
2. 点击扩展图标 → 侧边栏 → 点"读取诊断"。
3. 把诊断 JSON 复制到 docs/verification-results.md 模板。
4. 滚动加载更多 → 再读取一次 → 对比候选计数变化。
5. 换关键词"interpreter" → 再读取。
6. 打开笔记详情页 → 读取（预期得到明确错误提示）。
7. **新标签页**直接打开小红书 → 不点图标直接读取（预期 PERMISSION_DENIED 引导）。
8. 退出登录 → 读取（观察原始信号，用于阶段 3 编码 LOGIN_REQUIRED 判定）。

**预期结果**：探针在真实页面返回非空信号；错误路径文案清晰。**探针结果决定阶段 3 的正式选择器怎么写 —— 未实测前不得声称读取功能可用。**
