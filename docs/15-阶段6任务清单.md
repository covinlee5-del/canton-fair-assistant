## 3. 任务分解

### T6.1 选择器健康自检（2 天）

**要解决的问题**

`docs/10-选择器对照表.md` 里，标题/作者/摘要/时间四项至今是 `inferred`（值对，但不知道命中的是哪条候选选择器）。原因是升级需要人在 DevTools 里逐条核对——对非技术用户不现实。

**但插件自己就能回答这个问题。**

**做法**

1. 在 `src/content/adapters/selectors.ts` 增加一个诊断函数：对每条 `SelectorRule` 的**每一个候选选择器**分别统计命中数。

```ts
export interface SelectorHitReport {
  field: string;
  candidates: { selector: string; hits: number }[];
  chosen: string | null;     // 实际生效的那一条
}
export function reportSelectorHits(doc: Document): SelectorHitReport[];
```

2. 把它塞进 `ExtractionDiagnostics`（新增字段，例如 `selectorHits`），随「复制诊断 JSON」一起导出。
3. 侧边栏诊断区加一个折叠块「选择器命中详情」，表格显示：字段 | 选择器 | 命中数 | 是否生效。
4. 有了这个，人类点一次「读取」就能拿到证据，`docs/10` 的 `inferred` 可以凭数据升级为 `measured`。

**重要边界**

- 这只加**观测**，不改任何选择器语义、不改提取结果。`SELECTOR_VERSION` 是否需要 bump 由人类决定（建议 bump，因为诊断输出变了）。
- 自检必须**只读**：不点击、不滚动、不写页面。
- 大页面下 `querySelector` 遍历 20+ 条选择器会有性能开销，改为每次读取只算一次并缓存。

**验收**

- 诊断 JSON 里能看到每条候选选择器的命中数。
- 侧边栏能显示这张表。
- 对已知 fixture（`tests/fixtures/search-page.html`）断言：标题字段命中的是预期那条。
- 真实页面上跑一次，把结果回填 `docs/10`，把能升级的项从 `inferred` 改成 `measured`。

### T6.2 平台改版回归协议（1.5 天）

**要解决的问题**

小红书改版是必然事件。现在没有任何流程告诉后来者「改版了该怎么办」。

**要做的事**

1. **写一份回归协议**（新建 `docs/16-改版回归协议.md`，或并入 `docs/04`）：
   - 症状识别：侧边栏报 `NO_VISIBLE_NOTES` / `DOM_STRUCTURE_CHANGED` / `EXTRACTION_PARTIAL` 分别意味着什么
   - 采集步骤：用 T6.1 的自检表确认是哪条选择器失效
   - 修复流程：改 `selectors.ts` → 更新 fixture → bump `SELECTOR_VERSION` → 更新 `docs/10` → 跑三项命令
   - 回归验证：真实页面重新核对 §8 的 11 项
2. **fixture 重建脚本**：现在 `tests/fixtures/*.html` 是手工摘的。写一个本地脚本（放 `.local-verify/`），把真实页面的**匿名化结构**导出成 fixture。必须匿名化：替换标题、作者、ID、图片 URL。
3. **改版检测前置**：`detectStructureChange` 已有，但只在「卡片在却取不出」时报。补充一个「提取率骤降」信号：若某次读取 `extracted / totalCandidates < 0.5`，在诊断里给出警告（不是错误码，避免误报）。

**红线**：fixture 必须匿名化后才能进仓库。真实笔记标题、作者、图片 CDN 地址一律替换。

**验收**

- 协议文档存在，且步骤能被非技术用户跟着做。
- fixture 重建脚本可用，产物过一遍匿名化检查（`grep` 真实标题无命中）。
- 提取率骤降时有可见提示。

### T6.3 稳定性加固（2 天）

**现状核查结果（2026-10-19 实测）**

| 项 | 现状 | 结论 |
|---|---|---|
| React 错误边界 | **不存在**（无 `ErrorBoundary` / `componentDidCatch`） | 任一组件抛错 → 整个侧边栏/管理页白屏 |
| 网络请求 | **0 处**（无 `fetch` / `XHR` / `WebSocket` / `sendBeacon`） | 本地优先成立，见 T6.5 |
| 剪贴板写入 | 4 处（`copy.tsx:90`、`note-actions.ts:87,103`、`read-result.tsx:65`） | 都是用户点击触发，合规 |
| 危险 DOM 操作 | **0 处**（无 `.click(` / `scrollIntoView` / `execCommand` / `dispatchEvent(`） | 只读原则成立 |

**要做的事**

1. **加错误边界**：`src/ui/shared/components/ErrorBoundary.tsx`，包住侧边栏与管理页的根组件。
   - 抛错时显示："页面出现异常，你的数据没有被修改" + 错误码 + 「重新加载」按钮。
   - 不要在边界里吞掉错误后假装正常（那会违反"绝不显示成功"的原则）。
2. **大列表性能**：笔记页当前一次性渲染全部行。用 `uiPrefs.pageSize` 做分页或虚拟滚动；统计页在服务层聚合，不渲染全量。
3. **Service Worker 生命周期**：
   - 确认 SW 休眠后消息仍能唤醒（MV3 下 `register` 的监听器必须在顶层同步注册，不能在异步回调里注册）。
   - `Service Worker（无效）` 是**正常休眠状态**，不是错误——文档里已经写死，别去"修"。
4. **并发写**：用户快速连点「批量标为已审核」两次会怎样？加按钮禁用（进行中态），并在服务层做幂等（重复设置同一状态时 `canTransition` 返回 true，不应重复写活动记录——检查现有实现是否已处理）。
5. **存储配额**：`chrome.storage.local` 有 10MB 上限（`unlimitedStorage` 未申请）。设置很小不会有问题，但要确认 `keepDiagnostics` 不会把历史诊断无限累积。

**验收**

- 故意在组件里 `throw`，页面显示错误边界而不是白屏。
- 1000 条笔记时笔记页仍可操作。
- 连点批量按钮不会产生重复活动记录。

### T6.5 红线合规自动守护（1 天）

**要解决的问题**

`AGENTS.md` §2 的五条红线现在只写在文档里，靠人自觉。工具改了代码没人拦得住。

**要做的事**

新建 `tests/unit/red-lines.test.ts`，用**静态扫描源码**的方式守住红线：

| 红线 | 断言 |
|---|---|
| 1. 不自动发布/点赞/关注/私信 | `src/**` 内不得出现 `.click(`、`.submit(`、`dispatchEvent(` |
| 2. 不绕过登录/验证码 | `src/**` 内不得出现 `document.cookie` 赋值、`localStorage.setItem` 存凭证、伪造 `xsec_` 签名 |
| 3. 不调私有 API | `src/**` 内不得出现 `fetch(`、`XMLHttpRequest`、`axios`、`WebSocket`、`sendBeacon` |
| 4. 不上传凭证 | 同上 + 断言 `openUrl` 不进入任何导出路径（配合 T5.5） |
| 5. 无默认上传 | 同上 |

实现方式：读 `src/` 下所有 `.ts/.tsx`，对禁止模式做正则扫描，命中即 `expect(...).toHaveLength(0)`，并打印命中文件与行号。

**注意事项**

- 扫描要**排除注释**，否则文档里写了 `fetch` 也会误报。建议先剥离 `//` 与 `/* */` 再匹配。
- 剪贴板写入要**白名单**：只允许当前 4 处，新增必须显式改白名单（这样新增会被 review 注意到）。
- 这个测试的价值在于：**红线从"文档约定"变成"CI 阻断"**。

**验收**

- 测试通过。
- 故意加一行 `fetch('http://x')` 进去，测试必须失败（写完自己验一次，别只写不验）。

## 6. 红线与风险

### 6.1 红线

1. 自检、诊断功能**只读**：不点击、不滚动、不写页面。
2. fixture 必须匿名化。
3. 不做遥测、不做崩溃上报、不做远程配置。
4. 发布包不得包含源码与任何真实数据。
5. 错误边界不许把失败伪装成成功。

### 6.2 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 小红书改版频率高 | 选择器随时失效 | T6.1 自检 + T6.2 协议，把修复时间压到小时级 |
| 选择器自检遍历开销 | 读取变慢 | 每次读取只算一次并缓存 |
| 红线扫描误报 | 开发者绕过测试 | 剥离注释后再扫描；命中时打印行号便于判断 |
| IndexedDB 版本不可降级 | 用户回退扩展后白屏 | T6.4 显式捕获并给文案 |
