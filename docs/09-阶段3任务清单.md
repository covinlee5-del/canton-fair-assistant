## 3. 关键设计约束（写代码前先对齐）

1. **选择器集中且带版本号**：只允许出现在 `selectors.ts`，`SELECTOR_VERSION` 随实测结果升级；文档 §2 对照表同步更新。
2. **主键用 `noteId`，不用位置**：卡片 DOM 会复用/重排，位置不可靠；`noteId` 从 `/explore/<24位十六进制>` 或 `/discovery/item/<id>` 解析。
3. **绝不静默失败**：匹配为 0 → `NO_VISIBLE_NOTES`；结构明显变化 → `DOM_STRUCTURE_CHANGED`；未登录/风控 → 只提示，不绕过。
4. **只读可见范围**：不自动滚动、不翻页、不请求接口；用户滚动后再点读取，属于新一轮读取。
5. **单次扫描设上限**（建议 300 张卡片），超出部分提示"请滚动后再次读取"，避免卡顿。
6. **文本长度截断**：标题 ≤ 120 字符、摘要 ≤ 200 字符，防止数据库膨胀。
7. **数据只进本地**：IndexedDB + `chrome.storage.local`，无任何网络请求（红线核查时逐条可核对）。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 小红书页面改版 | 提取全部失效 | 选择器版本化 + `DOM_STRUCTURE_CHANGED` 明确提示 + fixture 回归测试 |
| 虚拟滚动 / DOM 复用 | 取到错位数据（A 的标题配 B 的链接） | 每张卡片**从自身节点**取 href 解析 id 与字段，绝不跨节点拼接 |
| 懒加载未渲染 | 提取到空占位 | 只取 `noteId` 可解析的卡片；其余计入 `skippedCandidates` 并在诊断里显示 |
| 风控 / 验证码 | 读取失败 | 只提示用户自行处理（`CAPTCHA_OR_RISK_CONTROL`），不尝试绕过 |
| 大量卡片导致卡顿 | 侧边栏无响应 | 单次上限 + 分片处理（`requestIdleCallback` 或分批 `setTimeout`） |
| 数据重复增长 | 列表噪音 | `noteId` 唯一 + upsert 语义 + 单测覆盖 |
