# 07 - AI 协作操作指南（给不写代码的人）

仓库：<https://github.com/covinlee5-del/canton-fair-assistant>

---

## 0. 先纠正一个误解

「DeepSeek 和 ChatGPT 同时控制这个项目」——**做不到，也不需要**。

Git 仓库同一时刻只能有一个「手」在写。多个 AI 同时改同一个文件，结果是互相覆盖、冲突、丢代码。
正确的模型是：**一份代码，三个 AI 轮流用**，你当「接线员」决定这一轮谁动手。

## 1. 三个工具的真实能力（重要）

| 工具 | 能读代码 | 能直接改仓库 | 说明 |
|---|---|---|---|
| **DeepSeek**（本机这个会话） | ✅ 直接读 `D:\RDplug-in` | ✅ 我能帮你 commit + push | 因为我在你电脑上，且你的 GitHub 凭据已存在本机 |
| **ChatGPT**（网页版） | ✅ 公开仓库能读 | ⚠️ 需要你授权「GitHub 连接器」后能开 PR | 没授权就只能聊，改不了 |
| **Grok** | ✅ 能读公开网页 | ❌ 基本不行 | 没有官方的 GitHub 写入连接，只能给建议 |

> 「给我开个 PR」= 它把改动放在一个分支上，让你点一下合并。**合并权永远在你手上**，这是好事。

## 2. ChatGPT 接入步骤

### 第一步：授权 GitHub

1. 打开 <https://chatgpt.com> 并登录
2. 点左下角头像 → **设置（Settings）**
3. 找 **连接器（Connectors）/ 应用（Apps）** 这一栏
4. 搜索 **GitHub** → 点连接
5. 浏览器跳到 GitHub 授权页 → 选择 **Only select repositories（仅选定仓库）**
6. 只勾 `canton-fair-assistant` → **Authorize**

> 为什么只勾一个：万一哪天它被说服去做危险操作，损失可控。

**如果你的设置里根本没有「连接器 / Connectors」**：说明当前套餐不支持 → 跳到 §5 的「粘贴法」，一样能干活。

### 第二步：验证它真的读到了

新开一个对话，直接发：

```
读我的 GitHub 仓库 covinlee5-del/canton-fair-assistant，
先看 AGENTS.md 和 README.md，然后告诉我：当前做到第几阶段、下一步该做什么。
```

它应该说得出「阶段 2 完成、阶段 3 未开始（小红书选择器还没实测）」。
**如果它答不出来，就是没连上，别急着让它改代码。**

### 第三步：让它改东西

给它明确指令，别只说「优化一下」：

```
按 AGENTS.md 的规范，修改 src/content/adapters/xiaohongshu-adapter.ts，
把 extractVisibleNotes() 的标题提取补上，要求：
1. 不改动红线（不自动操作）
2. 不猜选择器，先读 docs/verification-results.md
3. 提交到新分支 fix/note-title，然后开 Pull Request
```

### 第四步：你合并

1. 打开 <https://github.com/covinlee5-del/canton-fair-assistant/pulls>
2. 点进那个 PR → **Files changed** 看改了哪些（看不懂就看行数，改动越小越安全）
3. 点 **Merge pull request** → **Confirm merge**

### 第五步：让本地同步（关键，别忘）

回来跟我说一句：**「同步一下最新代码」**。
我会 `git pull` 把远程的改动拉到 `D:\RDplug-in\canton-fair-assistant`。
**不同步的话，你本机打开的还是旧代码。**

## 3. Grok 怎么用

Grok 没有官方 GitHub 写入连接，所以它的定位是**审稿人 / 点子来源**，不是施工队。

### 用法 A：让它读仓库提意见

在 <https://grok.com> 发：

```
读 https://github.com/covinlee5-del/canton-fair-assistant
重点看 AGENTS.md、docs/02-技术架构.md、docs/03-数据模型.md，
挑出 3 个最可能出问题的地方，并说明理由。
```

### 用法 B：让它写代码，但由别人落地

1. 让它产出**完整文件内容**或**补丁**（明确说："给我可以直接替换的完整文件"）
2. 复制它给的内容
3. 贴到我这边的对话里，说「按这个替换 `src/xxx.ts`」
4. 我写进本地 → 跑 `npm run typecheck` / `npm test` → 通过才提交

> 为什么不让 Grok 直接上：它看不到你本机的实际文件，容易把已改过的代码覆盖回旧版。
> 经过我这道「落地 + 编译校验」，能挡住大部分拍脑袋的代码。

### 用法 C：交叉复核（最有用的一招）

ChatGPT 或我改完 → 把 diff 贴给 Grok → 问「这段有没有安全问题 / 有没有违反红线」。
两个不同模型互相挑错，比一个模型自说自话靠谱。

## 4. 三种推荐工作流（选一个习惯就够）

### 工作流 1：以本机为准（最稳，推荐新手）

```
你说需求 → 我改本地 → 我先跑 typecheck/test → 我 push
        → 你把改动贴给 ChatGPT/Grok 复核
```

优点：只有一只手在写，永不冲突。

### 工作流 2：ChatGPT 主写

```
你让 ChatGPT 改 → 它开 PR → 你点 Merge → 你说「同步」 → 我 pull
```

优点：不用等我在线。缺点：它改的东西没跑过测试，合并后可能编译不过 —— 所以合并前让我看一眼。

### 工作流 3：Grok 出主意

```
Grok 提方案 → 你决定 → 让 ChatGPT 或我实现
```

## 5. 没有连接器时的「粘贴法」（永远可用）

1. 打开 <https://github.com/covinlee5-del/canton-fair-assistant>
2. 进到具体文件 → 点右上角 **Raw** → 全选复制
3. 贴给 ChatGPT / Grok，说"这是现状，帮我改成 X"
4. 把它给的完整文件贴回给我，我负责写入并验证

笨，但 100% 能用，而且不涉及任何授权。

## 6. 安全与踩坑清单

| 事项 | 说明 |
|---|---|
| 仓库是**公开**的 | 全世界的 AI 和人都能读。真实客户数据、文案库、密钥**绝不能**提交 |
| 只授权这一个仓库 | 别在 GitHub 授权页点「All repositories」 |
| 一次只让一个 AI 写 | 两个 AI 同时改同一文件 = 冲突 |
| 合并前先看 diff | 特别留意 `src/content/`（碰页面的地方）和 `package.json`（依赖） |
| 改完记得「同步」 | 远程变了本地不变，你打开的是旧代码 |
| 不小心提交了密钥 | 立刻告诉我，我来做 `git rm --cached` + 改写历史，**并去 GitHub 把那个密钥作废重发**（作废才是关键） |

## 7. 一句话总结

- **我（DeepSeek）**：能读能写，是「本地施工队」。
- **ChatGPT**：授权后能开 PR，是「远程施工队」，你点合并。
- **Grok**：只读，是「审稿人」。
- **你**：决定这一轮谁动手、点合并、记得让我同步。
